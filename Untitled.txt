The Goal (recap)

One chat box.

Session memory per conversation.

Gemini understands free-form requests and either:

executes Absence actions (e.g., “mark Manju absent today”), or

runs the SOW interview workflow entirely inside the same chat,

If a user asks for anything else, it politely refuses: “I can help only with Absence and SOW generation.”

High-level Architecture (what works best in practice)
1) Orchestrator (Backend “Brain”)

A single backend service (Node/TS or Python) that:

Wraps Gemini (system prompt + function/tool calling).

Holds a finite state machine (FSM) for the chat session:

IDLE → ABSENCE_SESSION → IDLE

IDLE → SOW_SESSION → SOW_INTAKE → SOW_REVIEW → SOW_RENDER → IDLE

Decides which domain (Absence/SOW) a message belongs to, using:

Deterministic rules (fast regex / keyword triggers for common phrasings),

Embedding intent check (text-embedding-004),

Gemini “router” pass (a super-short LLM prompt that returns {domain, confidence}),

Active mode bias: if already inside SOW intake, keep it unless the user explicitly exits.

This “belt-and-suspenders” routing keeps latency low and accuracy high.

2) Tools (Function Calling) as the Only Way to Act

Expose both apps to Gemini as tools with strict JSON schemas. Gemini never touches your DB directly; it can only call tools you define. Examples:

Absence tools

mark_absent(employee_id: string, date: string, reason?: string)

mark_present(employee_id: string, date: string)

get_employee(query: string) -> { employee_id, name, … }

get_absence_status(employee_id: string, date?: string)

list_team_absences(date: string)

SOW tools

start_sow_session(project_name?: string)

set_contact_info(oracle_rep, billing_contact) // nested fields

add_services(items: ServiceItem[])

add_deliverables(items: DeliverableItem[])

set_acceptance_criteria(text: string)

set_terms_fixed(template_id: string) // your “always same” sections

generate_sow_docx(options: { template_id, branding, format }) -> file_url

summarize_current_sow()

cancel_sow_session()

Each tool returns structured results (status, data, user-message suggestion).

3) Memory & State

Conversation log: Postgres table keyed by session_id; store user msg, model msg, tool calls, and tool results.

Working memory (FSM): a compact JSON blob in Redis keyed by session_id (fast read/write): mode, active_sow_id, collected_slots, last_tool_called, etc.

Vector memory (semantic recall): important snippets (last N tool results or user constraints) stored with pgvector (or a light vector DB). Use at re-prompt time to give Gemini grounded context without dumping the whole history.

4) Guardrails (stay on domain)

System Instruction tells Gemini: “You ONLY help with Absence and SOW. If outside scope, refuse with a friendly one-liner.”

Response Schema: always return a compact envelope:

{
  "mode": "IDLE|ABSENCE|SOW",
  "intent": "mark_absent|start_sow|…",
  "slots": { ... },
  "tool_call": { "name": "...", "args": { ... } } | null,
  "message_to_user": "..."
}


Server-side validator: if the tool name/args aren’t allowed for the current mode, reject and reprompt Gemini with a short “tool args invalid, try again” message.

5) UI (React/Next + WebSocket)

Crisp chat pane + small “Session Pill” at the top: Idle, Absence, SOW (Intake/Review/Render).

Inline cards for tool results (e.g., “✅ Marked Manju absent for 2025-10-03”).

Sticky composer suggestions: context-aware chips like Mark today, Show status, Continue SOW, Finish & Export.

History drawer (per session).

Everything happens inside chat. No page hops.

The Router (rock-solid intent with low latency)

Heuristics first (cheap):

/(absent|present|leave|sick|PTO|attendance)/i → ABSENCE

/(sow|statement of work|deliverable|acceptance|milestone)/i → SOW

Embedding cosine to two canonical intent centroids (Absence vs SOW).

LLM tie-breaker (very short prompt) if #1 and #2 disagree.

Return {domain, confidence}. If confidence < 0.6 and not already inside a mode, reply: “I can help only with Absence and SOW—what would you like to do?”

Keeping SOW “inside the chat”

Use a mini-DSL / slot map so the agent knows exactly what’s left:

{
  "required_slots": {
    "contacts.oracle_rep": "object",
    "contacts.billing_contact": "object",
    "services": "array",
    "deliverables": "array",
    "acceptance": "string"
  },
  "fixed_sections": ["project_management", "cooperation", "assumptions", "transition", "terms"]
}


The FSM only allows: ask → fill → confirm → call tool. No free-form wandering.

Error-handling & Idempotency

Each tool call includes a client_request_id (UUID) so retries don’t double-write.

If a tool fails, Gemini gets a short error summary and must either:

fix arguments and retry, or

apologize and ask the user for a missing detail.

Security & Safety

Never expose raw DB. Tools whitelist exactly what’s legal.

Rate-limit per session.

Sanitize all file names / doc exports.

Log every tool call + args in audit_log.

Observability

Traces per turn (user msg → router → model call(s) → tool call(s) → final).

Redash/Grafana: latency, tool error rate, “reprompt” count (signals schema friction).

Evaluation harness: a YAML of 50–100 canonical prompts (“mark X absent,” “start SOW,” “out-of-scope”) run nightly to check accuracy.

// packages/orchestrator/src/index.ts
import { geminiClient } from "./llm";
import { router } from "./router";
import { fsm, getSession, saveSession } from "./state";
import * as AbsenceTools from "./tools/absence";
import * as SowTools from "./tools/sow";

export async function handleUserMessage(sessionId: string, userText: string) {
  const session = await getSession(sessionId);          // redis+pg snapshot
  const route = await router.decide(userText, session); // {domain, confidence}

  const llmInput = buildContext({ session, userText });
  const modelResp = await geminiClient.generateJSON({
    systemInstruction,
    tools: {
      ...AbsenceTools.registry,
      ...SowTools.registry
    },
    responseSchema: OrchestratorEnvelopeSchema, // Zod
    input: llmInput
  });

  const plan = OrchestratorEnvelopeSchema.parse(modelResp);

  if (plan.tool_call) {
    const result = await callTool(plan.tool_call);
    // append tool result and reprompt once if needed
    if (requiresFollowup(result)) {
      const follow = await geminiClient.generateJSON({ ...sameCtxWithToolResult });
      return finalize(follow, sessionId);
    }
    return finalizeWithToolResult(plan, result, sessionId);
  }

  return finalize(plan, sessionId);
}

export const registry = {
  get_employee: {
    description: "Resolve employee by name/email/id",
    schema: z.object({ query: z.string().min(1) }),
    handler: async ({ query }) => {
      const row = await db.oneOrNone("SELECT * FROM employees WHERE ...", [query]);
      if (!row) return { ok:false, reason:"not_found" };
      return { ok:true, data: { employee_id: row.id, name: row.name } };
    }
  },
  mark_absent: {
    description: "Mark employee absent on date (YYYY-MM-DD)",
    schema: z.object({ employee_id: z.string(), date: z.string().regex(/^\d{4}-\d{2}-\d{2}$/), reason: z.string().optional() }),
    handler: async ({ employee_id, date, reason }) => {
      await db.none("INSERT INTO absences ... ON CONFLICT DO NOTHING", [employee_id, date, reason ?? null]);
      return { ok:true, message:`Marked ${employee_id} absent on ${date}` };
    }
  }

"use client";
import { useState } from "react";

export default function ChatPage() {
  const [messages, setMessages] = useState<{role:"user"|"ai", text:string}[]>([]);
  const [input, setInput] = useState("");
  const [mode, setMode] = useState("IDLE");

  async function sendMessage() {
    const userMsg = { role: "user", text: input };
    setMessages([...messages, userMsg]);
    setInput("");

    const resp = await fetch("/api/chat", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ text: userMsg.text })
    });
    const data = await resp.json();

    setMode(data.mode);
    setMessages(m => [...m, { role: "ai", text: data.message_to_user }]);
  }

  return (
    <div className="flex flex-col h-screen">
      <div className="p-2 bg-gray-100 border-b">
        <span className="font-bold">Session Mode:</span> {mode}
      </div>
      <div className="flex-1 overflow-y-auto p-4 space-y-2">
        {messages.map((m,i) => (
          <div key={i} className={m.role==="user"?"text-right":"text-left"}>
            <div className={`inline-block px-3 py-2 rounded-lg ${m.role==="user"?"bg-blue-200":"bg-green-200"}`}>
              {m.text}
            </div>
          </div>
        ))}
      </div>
      <div className="p-2 border-t flex">
        <input className="flex-1 border rounded px-2"
          value={input} onChange={e=>setInput(e.target.value)}
          onKeyDown={e=>e.key==="Enter"&&sendMessage()}
        />
        <button className="ml-2 px-4 py-2 bg-blue-500 text-white rounded"
          onClick={sendMessage}>Send</button>
      </div>
    </div>
  );
}

async def orchestrate(user_msg: str, session_mode: str = "IDLE") -> ChatResponse:
    system_prompt = "You are an orchestrator for Absence and SOW only..."
    plan = await call_gemini(system_prompt, user_msg, session_mode)

    # Execute tool call if exists
    tool_result = None
    if plan["tool_call"]:
        tool = plan["tool_call"]["name"]
        args = plan["tool_call"]["args"]
        async with httpx.AsyncClient() as client:
            resp = await client.post(f"http://localhost:8000/{tool}", json=args)
            tool_result = resp.json()

    return ChatResponse(
        mode=plan["mode"],
        intent=plan["intent"],
        slots=plan["slots"],
        tool_call=plan["tool_call"],
        message_to_user=plan["message_to_user"] + (f" Result: {tool_result}" if tool_result else "")
    )
